Use **dn 0.0.37** as the current recommended CLI for device runners, Void
task-sync, and the post-0.0.34 planning workflow. This page is current product
guidance, not a historical changelog for every intermediate release.

Confirm the binary:

```bash
dn --version
```

Install from [Installation](/dn/installation/) (latest release) or pin
`--version v0.0.37`.

## What you get on 0.0.37

The large workflow shift landed in **0.0.34**. Releases through **0.0.37** keep
that model and harden it — especially device runners, denoise-task / Void sync,
land, and kickstart.

### Baseline from 0.0.34

- Durable planning and close-out: `meld → loop → land`. See the
  [v0.0.34 migration](/dn/v0034-migration/) guide.
- Structured execution with [`dn until`](/dn/workflows/#dn-until) and
  [`dn land`](/dn/workflows/#dn-land).
- Sandbox schema 1.1 for Docker and exe.dev ([Sandbox](/dn/sandbox/)).
- Shared progress events for hosted kickstart
  ([Progress reporting](/dn/progress-reporting/)).
- Device-runner CLI (`dn runner …`) for pairing, repository registration,
  heartbeats, and typed kickstart claims.

### Important fixes and additions through 0.0.37

- Device-runner job status, fail messages, service lifecycle, and publish modes
  (`none` / `pr` / `direct`).
- Local task store and task-sync heartbeat channel for Void / denoise-task work.
- Kickstart plan-skipping, steer, quieter attended output, and land/testplan
  prompt discovery for installed binaries.
- Tiered dn configuration and Actions bridge.

Upgrade any device still on 0.0.34–0.0.36 before relying on runner pairing or
task-sync behavior described in current docs.

## Developer device runners in denoise

Denoise can send kickstart and Void task-sync work to a paired macOS or Linux
checkout. Source, credentials, and compute stay on that device. Denoise never
silently moves a device job to hosted compute.

Requires **dn 0.0.37** or newer on the device.

- [Runners](/denoise/device-runners/) — pairing, registration, security
  boundary, and operations
- [Kickstart runtimes](/denoise/kickstart-runtimes/) — when to choose
  `device_runner` vs GitHub Actions or managed VMs
- [The Void](/denoise/void/) — free solo tasks relayed to `~/.dn/tasks/`

GitHub Actions remains the default kickstart runtime and stays on the planning
repository. Choose a named device and an **Execution checkout** explicitly in
the kickstart dialog. Device runners are always available in denoise; they are
not behind a deployment feature flag.

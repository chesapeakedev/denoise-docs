# Org workspace B-roll shot list

Record these clips from your **org** workspace milestone that is already
initialized and roughly half kickstarted. Use them as cutaway footage during
GitHub Actions waits and to show end-state results without re-running dispatches
on camera.

## Before you record

- [ ] Open the org workspace on the Roadmap.
- [ ] Open the **GitHub-linked** milestone (initialized, ~half kickstarted).
- [ ] Enable **Kickstart order** in the task filter row.
- [ ] Hide completed tasks if the list is long (eye icon in filter row)—optional.
- [ ] Identify specific tasks to feature (write issue numbers below):

| Role | Issue # | Notes |
| ---- | ------- | ----- |
| Complete + PR link | `___` | Kickstart chip shows Complete; PR link visible on row |
| Complete + PR link (backup) | `___` | Second example for variety |
| Open + complexity badge | `___` | Numeric badge from stack plan |
| Open + complexity badge (backup) | `___` | Shows work still in queue |
| Highest kickstart priority (open) | `___` | Top of kickstart-sorted list |

## Shots to capture (5–15 seconds each)

Record each shot as a separate take. Hold steady for 2–3 seconds at the end of
each clip so the editor has handles.

### Shot A — Kickstart order overview

- **Framing:** Full milestone view—header, DN setup row, task filter row, task
  list.
- **Action:** **Kickstart order** chip is ON. Slow scroll through the task list.
- **Purpose:** Show complexity badges and mix of open and completed tasks.

### Shot B — Completed kickstart with PR

- **Framing:** Tight on one task row with **Complete** kickstart chip and **PR**
  link.
- **Action:** Hover or pause on the PR link (do not navigate away unless you
  want a separate GitHub tab clip).
- **Purpose:** Proof that kickstart opens pull requests.

### Shot C — Second completed task

- **Framing:** Another completed row, or slow pan across two completed rows.
- **Purpose:** Reinforce that multiple issues can be kickstarted in parallel.

### Shot D — Open task with complexity badge

- **Framing:** Task row showing numeric complexity badge, status Open.
- **Purpose:** Contrast with completed work—stack order guides what is next.

### Shot E — Repository and dn setup panel

- **Framing:** Expand **Repository & dn setup** collapsible panel.
- **Action:** Brief pause on suggested kickstart targets and setup summary.
- **Purpose:** Context for init_stack value without clicking Run.

### Shot F — Task detail with kickstart complete (optional)

- **Framing:** Open a completed task in the task detail dialog.
- **Action:** Show kickstart status and **Watch on GitHub** or PR reference if
  present.
- **Purpose:** Dialog-level confirmation of dispatch results.

### Shot G — Non-GitHub milestone (org)

- **Framing:** Switch to the **non-GitHub** milestone in org workspace.
- **Action:** Show task list; optional 3-second **Add task** click.
- **Purpose:** Grounding beat—planning without GitHub (used in intro segment).

### Shot H — Roadmap cards (org)

- **Framing:** Org Roadmap with workspace selector visible.
- **Action:** Pan across milestone cards; pause on GitHub indicator on linked
  card.
- **Purpose:** Intro and outro B-roll.

## What not to record here

- Do not click **Run dn.init_stack** or **Kickstart!** on this milestone during
  B-roll unless you want a deliberate re-run (skip for a 3–5 minute cut).
- Do not walk through Profile, Workbench, or Focus timer.
- Do not narrate during B-roll if you plan to voice over in edit—capture clean
  UI footage only.
